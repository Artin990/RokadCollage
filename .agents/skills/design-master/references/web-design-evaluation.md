# 网页设计评价标准（行业基准）

> 评价一个网页"好不好"，有一套成熟、可执行的行业标准。它不是审美玄学，而是围绕**用户体验、可访问性、响应式、性能、一致性、SEO、安全隐私**七大维度展开的可检查清单。
> 来源权威：W3C WCAG（Web 内容可访问性指南）、ISO 9241-151（人机交互人体工程学）、Google / Microsoft 设计最佳实践、Ant Design 等设计系统。

---

## 〇、为什么"看起来怪"——常见根因速查

用户常反馈"页面看着别扭/怪"，多半不是单一问题，而是以下根因之一。诊断时优先对照：

| 观感症状 | 最可能根因 | 对应维度 |
|---------|-----------|---------|
| 按钮/卡片大小不一、圆角混乱 | 缺设计令牌，元素未走统一规范 | 一致性 |
| 重点不突出，不知道看哪 | 缺视觉层级（字号/对比度阶梯混乱） | 可用性/一致性 |
| 手机上挤、错位、要横滑 | 非响应式，移动端未优先 | 响应式 |
| 留白忽大忽小、对不齐 | 无间距阶梯、栅格未对齐 | 一致性 |
| 图标与文字不在一条线 | 基线对齐缺失 | 一致性 |
| 颜色发"脏"、看不清字 | 对比度不足 / 色彩空间混乱 | 可访问性 |
| 动效卡顿、页面慢 | 资源未优化、装饰过重 | 性能 |
| 表单报错说不清、提交无反馈 | 缺交互反馈与清晰提示 | 可用性 |
| 键盘 Tab 乱跳、读屏读不出 | 未做无障碍（语义/标签/焦点） | 可访问性 |

**诊断口诀**：先看一致性（最常被忽略）→ 再看层级与对比 → 再看响应式 → 最后查性能与无障碍。

## 一、可用性与用户体验（Usability & UX）
基石。核心是让用户**轻松、高效**完成任务。

- **清晰的导航**：一致的导航位置；面包屑、清晰标题让用户随时知道"我在哪"；多页站点提供站内搜索。
- **直观的交互反馈**：点击/悬停即时视觉反馈；表单提交成功或出错，给出**清晰、显眼**的提示。
- **简洁的内容**：平实易懂的语言、段落简短；用标题和留白让结构清晰、易于扫读；**标题尽量一行内**。
- **用户优先**：做设计权衡时，始终把用户需求放首位。

**检查项**：导航是否一致可定位？操作有无即时反馈？表单/异常有无明确提示？内容是否扫读友好？

## 二、可访问性与包容性（Accessibility · WCAG POUR）
好设计服务所有人（含残障）。WCAG 核心四原则：

- **可感知 Perceivable**：为图片提供 alt 文本；文本与背景对比度充足（正文 ≥ 4.5:1，大字 ≥ 3:1）。
- **可操作 Operable**：所有功能可键盘操作；**不只用颜色传递信息**（如"必填"不能仅靠红字）。
- **可理解 Understandable**：信息与操作易理解；每个表单输入框配清晰 `<label>`。
- **鲁棒 Robust**：内容能被各种浏览器与辅助技术（屏幕阅读器）正确解析。

**检查项**：对比度达标？图片有 alt？键盘可达？表单有 label？不只靠颜色表意？

## 三、响应式与多设备适配（Responsiveness）
用户用各种设备访问，任何屏幕都要好用。

- **弹性布局**：流式布局 + 媒体查询，布局随屏幕尺寸灵活调整。
- **自适应内容**：按屏幕分辨率加载合适尺寸图像（手机/平板/桌面都流畅）。
- **移动优先**：优先为移动端设计，再渐进增强适配大屏。

**检查项**：320px / 768px / 1440px 三档是否都正常？图片是否按需加载？是否移动优先？

## 四、性能与加载速度（Performance）
加载慢严重损害体验与 SEO。

- **优化资源**：压缩图片、用现代格式（WebP/AVIF），减少加载时间。
- **轻量化设计**：避免不必要的装饰，保持简洁高效。
- **渐进增强**：核心内容与功能在旧浏览器也可用，再为现代浏览器增强。

**检查项**：首屏是否快速？图片是否压缩？有无多余重装饰/阻塞资源？

## 五、视觉与品牌一致性（Consistency）
统一视觉建立信任、强化品牌。

- **统一设计语言**：同类元素（按钮/标题/图标）用一致的颜色、字体、样式。
- **标准化布局**：搜索框、导航栏等通用功能放在一致位置。
- **设计系统**：建立规范与组件库——保证一致性，也提升团队协作与开发效率。

**检查项**：有无设计令牌/组件库？同类元素是否统一？通用模块位置是否一致？

## 六、搜索引擎优化（SEO）
好设计兼顾被搜索引擎理解。

- **语义化 HTML**：用正确标签（`<header>` `<nav>` `<article>` `<main>`）构建页面。
- **优化元数据**：准确且吸引人的 `<title>` 与 `<meta description>`。

**检查项**：是否语义化标签？title / meta description 是否到位？

## 七、安全与隐私（Security & Privacy）
值得信赖的网站必须保护用户。

- **安全是基础**：使用 HTTPS 保护用户数据。
- **可信 UI**：地址栏、权限提示等关键元素不被网站伪造/劫持。
- **用户控制**：自动播放的动画/声音/视频提供显式开关。

**检查项**：是否 HTTPS？有无伪造风险界面？媒体是否可关？

## 八、评分 rubric（设计大师据此给页打诊断）

| 维度 | Pass ✅ | Warn ⚠️ | Fail ❌ |
|------|---------|---------|---------|
| 可用性 | 导航清晰、反馈即时、内容扫读友好 | 部分缺失（如反馈弱） | 核心任务无法顺畅完成 |
| 可访问性 | 对比度达标、键盘可达、有 alt/label | 部分达标 | 残障用户基本不可用 |
| 响应式 | 三档屏幕均正常、移动优先 | 仅桌面好 | 移动端错位/横滑 |
| 性能 | 首屏快、资源轻 | 略重 | 明显卡顿/慢 |
| 一致性 | 有令牌/组件库、统一 | 局部不一致 | 各自为政 |
| SEO | 语义化+元数据完整 | 部分 | 全无 |
| 安全隐私 | HTTPS+可控媒体 | 部分 | 风险界面/无控制 |

**输出格式**：逐维度给 ✅/⚠️/❌ + 一句话问题 + 一句修复建议；最后给"最该先改的 1-3 项"（按影响面排序，通常先一致性/层级/响应式）。

## 九、权威来源（论断出处）
- W3C WCAG（Web 内容可访问性指南）
- ISO 9241-151（人机交互人体工程学）
- Google Web Fundamentals / Microsoft Fluent Design 最佳实践
- Ant Design / Material Design 等设计系统规范

> 这些标准是"指导原则"，不是条条框框。优秀的网页设计是以人为本的：可用、包容、快速、一致、安全、可被发现的。
